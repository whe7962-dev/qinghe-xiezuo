## 一句话说清这是什么

一个本地网页：上传「任务表」和一批「聊天记录」，真实调用外部对话模型分析出**字段级建议**（原值、建议值、依据原话、不确定点），由人逐条采纳／否决／修改后采纳，只有确认的建议才写回任务表，最后导出新任务表 + 建议清单 + 变更说明；下一批聊天接在上一次确认结果上继续，重复导入不重复、不覆盖。

## 开发必须守住的 6 条

1. **分析必须真实调用外部对话模型。** 不许预写答案、不许用纯规则替代分析、不许把别处生成的答案粘进网页。
2. **不许把附件里的处理结论写死在程序里。** A 批／B 批的结果只能作为测试期望，不能作为代码常量。
3. **使用者确认之前，任务表不变。** 只有「采纳」「修改后采纳」写回对应字段；程序不得替人确认。
4. **字段级更新。** 改责任人不许顺带动日期；同一行其余字段逐字保持。
5. **重复导入必须幂等。** 同一批相同编号相同正文再导入 → 不新增行、不重复产生建议、不覆盖已确认字段。
6. **失败必须可见。** 模型调用失败／超时／调用超限时，页面进入失败状态，已确认的任务表和决定保留，可重试。

## 参考实现怎么跑

`05-参考实现（skeleton）/` 是一份能跑起来的参考代码（Python 3.10+），**不是验收基线**，可按需改造或完全重写。

```sh
cd 05-参考实现（skeleton）
./run.sh          # 首次会生成模板 .env 并提示填密钥
# 填好 .env 后再次执行，打开 http://127.0.0.1:8000
```

```sh
.venv/bin/python -m pytest -q     # 20 项测试，不需要真实密钥
```

- 密钥只从 `.env` 读，页面与日志不展示。
- 模型服务地址、模型名由 `.env` 注入，可切任意 Anthropic-compatible 网关。
- 目录：`app/`（业务与 API）、`web/`（页面）、`tests/`（测试）、`exports/`（运行时产物，自动生成）。
- ⚠️ **已知与验收基线的差距**：模型对「当前安排」类字段偏保守，倾向输出「不建议修改」，与 PRD 5.4 基线的期望叙述不完全一致；需靠提示词（`app/prompt.py`）调优拉齐。开发时应以 PRD 5.4 为准。
