# 前端适配声明

> 阶段 3-0。依据：PRD（V2，含 3.6 展示与交互规范）、技术适配声明、决策台账、后端接口（含 V2 字段）。

## 1. 项目判断
- 产品类型：本地网页工具（根据聊天记录更新任务表，单人使用）。
- 主要用户：任务表维护人（单人）。
- 主要终端：桌面 Web 为主，兼顾移动 Web（390px 基本可用）。
- 新项目或已有项目：已有项目——阶段 2-1 已产出**纵向切片界面**（会保留到正式产品）。
- 本阶段业务目标：把 V1 纵向切片界面升级到 **V2 交互规范**（PRD 3.6 + FR7–FR10）。

## 2. 输入资料
- PRD：已读取（V2，585 行，含 3.6 展示与交互规范 13 小节）。
- 技术适配声明与决策台账：已读取（D1–D9 已定）。
- 阶段 2 界面类型：**纵向切片（在其上继续开发，前端子阶段 1、2 合并，不另起平行工程）**。
- 接口文档：完整（后端已实现，含 V2 字段 urgency / decided_at / decided_by / reject_reason）。
- 设计稿：无（按中性方案先做一版代表页）。
- 现有代码：有（`frontend/`，Vite + TypeScript）。

## 3. 技术选择
- 框架与版本：Vite 5 + TypeScript strict（原生 TS，无 React/Next.js）；Node 24 + npm。
- 样式与组件策略：手写 CSS + CSS 语义变量（状态色、紧急程度色），无 Tailwind。
- 数据请求与状态策略：集中式 API 层（拆出 `src/api.ts`），以 `/api/state` 为状态事实来源。
- 流式通信策略：无（分析为同步接口，前端显示「处理中」）。
- 表单方案：原生 `<input type=file>` + `FormData`。
- 测试方案：ESLint + `tsc --noEmit` + `vite build` 为交付门槛；单页本地工具，核心逻辑已由后端 pytest 覆盖（28 项），前端暂不引入 Vitest 单测。
- 部署环境：`npm run build` 产物 `frontend/dist` 由 FastAPI 挂载，本地 8000。

## 4. Agent 状态
- 后端状态 → 前端映射：`planner.stage`（载入/分析/确认/导出）→ 顶部步骤条；`last_error` → 页内持久错误提示 + 重试按钮（不用阻断式弹窗）。
- 等待用户确认：建议卡片决定按钮（待确认/采纳/否决/修改后采纳）；因无撤销，**所有决定二次确认**（弹层展示原值→新值 + 「此操作不可撤销」）。
- 取消、重试、断线恢复：分析同步执行无取消；失败可重试；刷新后经 `/api/state` 恢复（后端 state.json 持久化）。
- 任务 ID 和恢复入口：单会话无任务 ID；恢复 = 刷新自动拉取 `/api/state`。

## 5. 页面与产物
- 核心页面：单页——步骤条 → 汇总条 → 载入区 → 分析区 → 核对区（按任务分组）→ 导出区 → 任务表区。
- 核心业务闭环：上传 CSV → 发起分析 → 逐条决定（二次确认）→ 写回 → 导出三份 → 下载。
- 产物类型和预览方式：`任务表.csv` / `建议清单.json` / `变更说明.md` 三份下载。
- 响应式目标：桌面 + 移动 390px 基本可用（任务表横向滚动）。

## 6. 偏离本手册的地方
- 偏离：Next.js App Router → Vite + 原生 TS；Tailwind CSS → 手写 CSS 变量；Lucide 图标 → 内联 SVG/字符图标；Vitest → 暂不引入。
- 原因：单页本地工具，无 SSR / SEO / 路由需求；界面为表单 + 卡片列表；避免引入需求未触发的框架（AGENTS.md 第 6 节禁止）。
- 影响：无（接口与业务仍在后端；交付门槛 lint / tsc / build 已满足）。
