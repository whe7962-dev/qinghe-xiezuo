# 技术适配声明

> 阶段 1 · 技术适配。产品：青禾协作。依据：PRD（定稿）+ 通用手册第一部分 + 决策台账（D1–D9 均已定）。

## 1. 产品形态判断
- 产品类型与核心任务：本地网页工具（单机、单人、不上线）。上传「任务表 CSV + 聊天记录 CSV」→ 真实调用外部对话模型产出字段级建议（原值 / 建议值 / 依据原话 / 不确定点）→ 人逐条采纳 / 否决 / 修改后采纳 → 只有确认的写回 → 导出三件套（任务表.csv / 建议清单.json / 变更说明.md）；重复导入幂等。
- 核心交互：分阶段确认（载入 → 分析 → 核对 → 确认 → 写回 → 导出 → 下一批 → 重复导入）；「逐条人工确认建议」是核心交互，程序不得代确认。
- 开发路径：**纵向切片**（人工确认属于 Agent 能力核心，先跑通一条端到端链路再扩展）。
- 验收界面：**纵向切片界面**（会保留到正式产品；从阶段 2 出现起按正式前端标准验收，需产品经理确认）。
- 上线套餐：不适用（台账 D9 = 只本机用，阶段 4 记为 N/A，不上线）。
- 当前阶段范围：阶段 2-1（后端 MVP + 最小纵向切片界面：完整核心闭环）。

## 2. 采用的默认方案
- 后端语言：Python 3.12.x（本地 python3.12 已就位，与上线镜像一致）。
- 后端框架：FastAPI。
- 数据校验：Pydantic（接口与模型结构化输出校验）。
- 测试：pytest（mock 用 FakeLLMClient，不调真实模型）。
- 代码管理：Git（已初始化，.gitignore 生效）。
- 模型调用：Anthropic SDK 走 DeepSeek anthropic-compatible 网关（服务地址 / 模型名 / 密钥由 `.env` 注入，页面不展示密钥）。
- CSV 读写：Python 标准库 csv，UTF-8 带 BOM。

## 3. 触发的按需模块
- 结构化文件持久化（JSON + schema 版本 + 原子写入）：由「跨批次连续、进程重启可恢复」触发，当前阶段引入（代替关系型数据库）。
- SQLite + SQLAlchemy：暂缓（单用户本地、数据量小、无并发）。
- SSE：不引入（PRD 6.2 已定稿「同步执行 + 处理中状态」）。
- 后台任务队列：不引入（PRD 6.2 已定稿「不引入后台任务」）。

## 4. 偏离或暂缓的默认方案
- 默认「SQLite + SQLAlchemy」→ 暂缓，改用结构化文件（JSON + schema 版本 + 原子写入）。原因：单用户本地，数据只有任务表 / 聊天 / 建议 / 决定 / 导出物，量小无并发。影响：无。未来：多用户、复杂筛选、并发修改时再迁移。
- 默认「正式前端 Next.js + TS + Tailwind」→ 阶段 2 纵向切片先用轻量工程化前端（Vite + TypeScript，含 lint / 构建 / 类型检查），阶段 3 在此基础上完善视觉与移动端。原因：本地单机工具、界面为表单 + 列表 + 按钮，无 SSR / SEO / 路由需求，避免引入未触发的框架。影响：无（接口与业务仍在后端）。

## 5. 强制底线检查
- 密钥与隐私：通过（`.env` 注入、页面不展示、日志不记密钥；`.env` 已进 `.gitignore`）。
- 数据与任务可恢复：通过（结构化文件 + 原子写入，重启可恢复；阶段 2 写 `scripts/restart-check.sh` 实测）。
- 输入输出校验：通过（Pydantic 校验接口；CSV 列缺失 / 格式错误明确报错；模型输出结构校验）。
- 错误与日志边界：通过（统一 `{"error":{code,message}}`，不泄露堆栈；本产品不用 SSE，无 SSE 收尾问题）。
- 测试与真实模型验收：mock 测试（FakeLLMClient）每次开发必跑；真实模型冒烟在验收前跑（无 Key 时如实记「待验」）；Agent 效果按台账 D3「事实一致 + 首次真实冒烟用 5–10 条样例定死」。
