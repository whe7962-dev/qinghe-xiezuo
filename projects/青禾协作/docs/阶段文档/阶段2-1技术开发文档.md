# 阶段 2-1 技术开发文档｜后端 MVP + 最小纵向切片界面

> 配套文档：`docs/PRD/PRD.md`（定稿）、`docs/阶段文档/技术适配声明.md`、AI Agent 产品 Vibe Coding 通用技术栈手册。
> 本阶段只做核心闭环，不提前做正式前端美化（阶段 3）、登录/多人（不做）、公网部署（不做，台账 D9）。

## 一、阶段目标
- 交付范围：完整核心闭环——上传任务表 + 聊天记录 → 真实调用模型分析 → 逐条核对建议 → 逐条确认 → 写回 → 导出三件套 → 载入下一批 → 重复导入幂等。
- 阶段产物：`backend/`（FastAPI）、`frontend/`（Vite + TypeScript 纵向切片界面，保留到正式产品）、`backend/tests/`（pytest mock）、`scripts/restart-check.sh`、`README.md`、`data/`（结构化文件持久化）。
- 验收标准：对齐 PRD FR1–FR6、业务规则 R1–R10、成功指标 5.5。
- 明确不做：登录/多人权限、接真实聊天软件、复杂历史系统、公网部署、正式前端视觉打磨与多终端（阶段 3）、关系型数据库（暂缓）。
- 主链路片段：载入 → 分析 → 核对 → 确认 → 写回 → 导出 →（下一批）→ 重复导入。

## 二、技术适配摘要
- 开发路径：纵向切片（人工确认是 Agent 能力核心）。
- 本阶段采用默认方案：Python 3.12 + FastAPI + Pydantic + pytest + Git；模型走 Anthropic SDK（DeepSeek anthropic-compatible 网关，配置注入）。
- 本阶段启用按需模块：结构化文件持久化（JSON + schema 版本 + 原子写入）。
- 本阶段偏离/暂缓：SQLite/SQLAlchemy 暂缓（单用户本地）；正式前端 Next.js 暂缓，纵向切片先用 Vite + TypeScript（含 lint/构建/类型检查）。

## 三、技术栈与模型
- 后端：Python 3.12、FastAPI、Pydantic、pytest、python-multipart、python-dotenv、anthropic。
- 前端：Vite + TypeScript（原生 TS，无框架）、ESLint；产物构建到 `frontend/dist/`。
- 模型：DeepSeek（`MODEL_ID` 默认 `deepseek-chat`，可切 `deepseek-v4-pro`；`ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`）。服务地址/模型名/密钥由 `.env` 注入，页面与日志不展示密钥。
- 明确不引入：数据库 ORM、SSE、后台任务队列（PRD 6.2 已定稿同步）。

## 四、环境与配置
- `.env.example`（不含密钥）：`ANTHROPIC_API_KEY`、`MODEL_ID`、`ANTHROPIC_BASE_URL`、`MAX_OUTPUT_TOKENS`。真实值填 `backend/.env`（已被 `.gitignore` 忽略）。
- 产品经理需提供：DeepSeek API Key（验收前提供即可；开发期用 mock 推进，无 Key 不阻塞开发）。
- 启动端口：后端 8000（`uvicorn app.main:app --port 8000`）；前端 dev 5173（仅开发期，验收用 `npm run build` 产物由后端挂载）。
- 依赖服务：无外部数据库/缓存；模型为唯一外部依赖。

## 六、数据、资产与状态
- 持久化方式：带 schema 版本的结构化文件 `data/state.json` + `data/exports/`（三份导出物）。原子写入（先写临时文件再 rename），损坏时回退到空状态并记录。
- `data/state.json`（schema_version=1）：
  - `tasks`：当前任务表（6 字段数组）。
  - `suggestions`：当前建议（含决定）。
  - `processed_keys`：已分析过的聊天去重键（`编号|正文`），支撑重复导入幂等。
  - `applied_fields`：已确认字段快照 `task_id -> {field: value}`，支撑"不覆盖已确认字段"校验。
- 状态机（`planner`）：空 → 已载入 → 已分析 → 已确认 → 已写回 → 已导出；`last_error` 记录失败，失败可重试且不丢已确认数据。
- 上传文件：只读入内存解析，不落盘；导出文件只写 `data/exports/` 内三个固定文件名，拒绝越出。

## 七、API 设计（统一错误 `{"error": {"code", "message"}}`）
| 方法 | 路径 | 请求 | 响应（ok 时） | 错误 |
| --- | --- | --- | --- | --- |
| GET | `/api/state` | — | 任务表/聊天/建议/阶段/错误 | — |
| GET | `/api/metrics` | — | 五项派生指标 | — |
| POST | `/api/load` | multipart：`task_csv`、`chat_csv` | 行数、新增/重复聊天数、受保护字段数 | 400 CSV 列缺失/为空/格式错误 |
| POST | `/api/analyze` | — | 建议列表 | 502 模型失败（无 Key/超时/解析失败），已确认数据保留 |
| POST | `/api/decide` | `{index, decision, modified_value?}` | 更新后的建议 | 400 决定非法/序号越界 |
| POST | `/api/apply` | — | 写回条数 | 403 无待写回 |
| POST | `/api/export` | — | 三份产物下载名 | 403 未写回/未分析 |
| GET | `/api/download?name=任务表.csv` | — | 文件（仅三份固定名） | 404 未知文件 |

- 分析为同步接口（PRD 6.2），前端请求期间显示「处理中」；单批 ≤3 次模型调用、≤3 分钟，超限进入失败状态。
- 不使用 SSE，无 SSE 事件序列。

## 八、Prompt 设计
- `app/prompt.py`：System 提示词把 R1–R10 编码为可执行指令，只输出严格 JSON `{"suggestions":[...]}`；正例含结构示范，反例明确禁止 Markdown 围栏、禁止编号偏离。
- 输出解析（`analyzer.py`）：确定性解析器宽容兼容围栏/前后解释；Pydantic 等价 schema 强校验；字段非法/缺 suggestions 判 ModelError 走有限重试，仍失败进失败状态。
- 数量/内容约束（如"某字段只给一条"）不遵守时记为瑕疵交产品经理判断，不反复重试烧钱。

## 九、验收界面（纵向切片，保留到正式产品）
- 功能上限：载入两个 CSV → 发起分析（处理中/完成/失败三态）→ 建议列表（原值/建议值/依据原话/不确定点）→ 逐条「待确认/采纳/否决/修改后采纳」→ 写回 → 导出三件套 → 下载。
- 目标终端：桌面 Web（阶段 2 只保证桌面宽度；移动端宽度阶段 3 完善，是否表第 7 项本阶段按桌面检查）。

## 十、测试要求
- 第一层 mock（pytest，FakeLLMClient，不调真实模型）：CSV 解析/导出 BOM、字段级写回、未确认不写回、A/B 批业务预期（W-01 四字段不改、B 批 W-01 责任人→周宁/截止日→19 日）、重复导入幂等、导出表可再载入、决定四态校验。
- 第二层真实冒烟（验收前，无 Key 记「待验」）：用 `个人资料/测试题A/` 三份 CSV 跑 A 批 → 核对 → 确认 → 导出 → B 批 → 重复导入，记录模型/耗时/调用次数/成本，按台账 D3 给 5–10 条样例打分。
- 重启恢复：`scripts/restart-check.sh`（起服务 → 写入带标记记录 → 杀进程 → 再起 → 按标记读回比对）。
- 错误路径：无 Key、错误 Key、超时、模型输出非法 JSON、CSV 列缺失、越界下载。
