# 第 3-1 阶段开发文档（前端）

> 配套：`docs/阶段文档/前端适配声明.md`、PRD（V2）第 3.6 节、AI Agent 产品 Vibe Coding 通用前端技术栈手册。

## 1. 本阶段目标
- 把阶段 2-1 的纵向切片界面升级为**飞书风格**的正式界面，实现 PRD 3.6 展示与交互规范 + FR7–FR10。

## 2. 范围
### 本阶段包含
- 页面：单页（步骤条 → 汇总条 → 载入区 → 分析区 → 核对区 → 导出区 → 任务表区）。
- 组件：建议卡片（三重编码）、任务分组折叠、二次确认弹层、否决理由输入、已核对勾选、紧急程度标记、决定留痕。
- 接口：`/api/state` `/api/load` `/api/analyze` `/api/decide` `/api/apply` `/api/export` `/api/download`。
- 任务状态：后端 `planner.stage` → 顶部步骤条（载入→分析→核对→导出）。
- 产物：三份导出文件下载。

### 本阶段不包含
- 登录/多人、接真实聊天软件、公网部署、复杂历史系统、分页/虚拟滚动（单批 ≤10 条）、撤销功能（PRD 明确不提供）。

## 3. 用户流程
1. 上传任务表 CSV + 聊天记录 CSV → 点「载入」→ 任务表显示、汇总条就绪。
2. 点「发起分析」→「处理中」→ 建议按任务分组、按紧急程度排序展示。
3. 逐条「采纳 / 否决 / 修改后采纳」（均二次确认，弹层写明「此操作不可撤销」）；否决可填理由。
4. 任务表每行可勾「已核对」（私人标记，不入表不入导出）。
5. 点「写回」→ 点「导出三份产物」→ 下载。

## 4. 页面状态矩阵（载入区 / 分析区 / 核对区）
| 状态 | 载入区 | 分析区 | 核对区 |
| --- | --- | --- | --- |
| idle | 文件选择 + 载入按钮 | 发起按钮 | 空提示「发起分析后…」 |
| loading | 载入中禁用按钮 | 处理中禁用按钮 | 保持 |
| empty | 提示未载入 | — | 「还没有建议」 |
| succeeded | 载入结果行数 | 分析完成 | 分组卡片 |
| failed | 错误提示 | 失败 + 可重试 | 保持已确认数据 |
| waiting_user | — | — | 卡片决定按钮 + 二次确认 |

（queued / streaming / partially_succeeded / cancelled / disconnected / stale / permission_denied / not_found：本产品同步分析、单会话、无鉴权，均 N/A。）

## 5. 接口契约
- 见阶段 2-1 技术开发文档第七节；本阶段新增字段（`urgency`/`decided_at`/`decided_by`/`reject_reason`）已在后端实现。
- 统一错误 `{"error":{"code","message"}}`；前端按 HTTP 状态 + `error.message` 展示，不泄露堆栈。
- 超时与重试：分析同步 ≤3 分钟；失败显示页内错误 + 重试按钮。

## 6. 实现方案
- 路由：无（单页）。
- 组件结构：`src/api.ts`（集中式接口层 + 类型）+ `src/main.ts`（渲染与交互）+ `src/style.css`（飞书设计变量与组件样式）。
- 状态来源：后端 `/api/state` 为唯一事实来源；前端不保存业务状态。
- 已核对标记：`localStorage`（本机会话），不写入任务表、不进导出物（3.6.8）。
- 流式/轮询：无（同步分析 + 前端「处理中」）。
- 响应式：桌面为主；移动 390px 下任务表横向滚动、卡片自适应。
- 安全：密钥不进前端；`<button>` 键盘可操作；状态三重编码（颜色+图标+文字）。
